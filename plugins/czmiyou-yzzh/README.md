# 衣装智换 · 0.5.0 统一登录客户插件预览

把本包交给 Codex 或 WorkBuddy，引导完成安装、登录、配置和使用。CZMIYOU 产品 ID 4 时间卡控制插件资格；客户自己的火山方舟账户承担生成费用，不扣 CZMIYOU 中央余额。默认自动上传素材，无需建桶或部署视频中转服务器；已有完整 TOS 配置继续沿用，用户可在高级设置切换。

本版仅面向 AIGC 虚拟人像场景：选择已有角色，或上传虚拟人像入库审核，Active 后复用人物 ID。素材库连接不等于真人活体认证；不提供真人授权入口，不要求完成真人认证。

沿用原来的 CZMIYOU 统一登录页。在「我的应用」点击「米哟衣装智换」，尝试唤醒本机插件并打开衣装页面；未检测到时前往 GitHub 下载。本包必须配合已更新的统一登录系统，不能只更新本地 ZIP 就改变线上按钮。保留原项目页面、四种替换和原有步骤；长视频的写实入口标为「写实虚拟人像」，原路由及数据不变。页面右下角提供账号、自己的 Key 和网络请求确认面板。原网页业务在按账号隔离的本地进程中执行。原本地拆镜已用合成视频实测；自动白模、表演分析、人物库和完整重绘的供应商实测仍待授权，不能当作全流程商用已验收。

Agent 可用 original_analyze 在原长视频流程创建本地拆镜任务、original_status 查看进度，之后回原页面继续。原 0.2 的 10 个单段工具仍保留；其任务查看和审批入口移至 /agent-workbench，与原页面任务不是同一套 ID。没有将全部原页面操作宣称为 MCP 工具。

原流程每次上传、生成或云端修改都会暂停，等待你在附加面板逐次确认；请求正文冻结并绑定账号与配置。包括原逻辑重试也必须再确认。没有价格估算，不批量自动同意；拒绝或超时不会外发。结果不明会留下记录并阻止新的云端修改，需要先在供应商控制台核对，不提供自动解锁或重发。

## 安装

使用构建后的完整 ZIP，不要直接安装源码骨架。客户需 Python 3.10+（推荐 3.12），首装联网下载依赖和基础本地模型。依赖及模型安装在解压目录，不修改全局 Python。没有 Demucs、PyTorch 或 CUDA 的强制依赖。

完整安装默认包含下面两项基础模型，安装前通过 `setup.py --dry-run` 展示下载内容、来源与保存位置。用户同意安装插件，即包含已告知的这两项基础依赖，无需再单独确认一次模型下载。模型文件合计约 50 MB，另需 Python 依赖及下载临时文件的空间。

| 基础模型 | 用途 | 下载来源与大小 |
| --- | --- | --- |
| OpenCV YuNet 2023mar | 本地人脸检测和打码 | [OpenCV 模型仓库](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)，约 230 KB |
| Depth Anything V2 Small FP16 ONNX | 本地深度参考 | `onnx-community` 转换版，优先 [ModelScope 镜像](https://modelscope.cn/models/onnx-community/depth-anything-v2-small)，备用 [Hugging Face](https://huggingface.co/onnx-community/depth-anything-v2-small)；49,642,442 字节，约 49.6 MB |

模型保存在固定运行安装目录的 `runtime/models`，不需要在 Codex 插件缓存重复下载。`health` 的 `local_dependencies` 只说明 Python 依赖可找到，不代表模型权重已齐；完整安装需通过安装脚本的模型加载及合成帧推理验证，才能报告打码、深度功能就绪。该验证在本机使用合成内容，不上传客户素材或调用付费生成。

进入工作台后，账号与创作设置中的「本地基础自检」会检查两项模型的完整性、实际加载推理和视频工具能否运行；缺失或损坏会给出补装提示。结果只代表本地基础功能，API Key 保存成功仍不代表供应商权限或付费生成已验收。模型文件变化后重新检查，不在创作过程中隐式下载。

1. 解压到固定位置，先运行 `python3 scripts/validate_release.py`，再运行 `python3 scripts/setup.py --dry-run` 查看安装影响。文件哈希校验不是发布者数字签名。
2. 用户确认安装后运行 `python3 scripts/setup.py`，一并安装依赖及上述人脸、深度模型；已有安装授权时直接继续，不重复征求确认。Windows 使用可用的 Python 命令。`--models` 保留兼容旧命令；只有用户明确选择不安装基础模型时才使用 `--skip-models`，并说明缺失模型对应的打码、深度功能不可用。已安装插件缺失基础模型时，运行 `python3 scripts/setup.py --models-only --dry-run` 查看补装内容，再使用 `python3 scripts/setup.py --models-only` 补齐；用户要求修复基础模型即涵盖已说明的补装。普通处理不会偷偷下载权重。
3. 运行 `python3 scripts/host_config.py` 输出不含 Key 的绝对路径 MCP 配置，在宿主的 MCP 配置入口添加。不要覆盖已有其他 MCP 配置。默认账号接口已内置：`https://mch39t7vkw.coze.site/api/auth/login`。仅管理员变更账号中心时指定 `--login-url`，不能填写不可信地址。
4. Codex 原生插件支持的入口使用 `.codex-plugin/plugin.json`；WorkBuddy 提供 `.workbuddy-plugin/plugin.json` 和手动 MCP 配置。宿主版本和 Windows/POSIX 启动命令需要分别核验。手动添加 MCP 后还需通过宿主技能导入入口导入 `skills/yzzh`。安装元数据有效不代表真实宿主已经安装成功。
5. 若要从网页点击后自动唤醒，先运行 `python3 scripts/register_launcher.py --dry-run` 查看影响。取得用户对注册本机启动器的明确同意后，再运行 `python3 scripts/register_launcher.py`。macOS 注册当前用户 Applications 下的专用启动器，Windows 只注册当前用户的 URL 协议；不修改其他宿主配置。只启动固定安装目录内的后台，不执行链接中的参数。首次点击浏览器可能要求确认打开应用。现有同名启动器不会自动覆盖，更新需另行确认；安装目录不能随意移动。Linux 暂不支持自动唤醒，可先让 Agent 打开插件。
6. 让 Agent “打开衣装智换工作台”，未登录时会打开原来的 CZMIYOU 统一登录页；选择正确身份登录，在「我的应用」点击「米哟衣装智换」。本地页面不再要求重复填密码。员工也不豁免产品 4 时间卡。统一登录令牌通过限定来源的一次性浏览器交接发送，本地后台再向账号中心验证，只保存在内存，不放进启动协议或 GitHub 链接；重启后重新从统一入口进入。新任务在线验证产品 4 时间卡，不检查中央余额。

本地后台默认 `127.0.0.1:7871`，项目位于用户目录 `.czmiyou-yzzh`。统一网页只检测默认 7871 端口；客户不要更改 `YZZH_PORT`，开发自定义端口不在自动发现范围内。`YZZH_DATA_DIR` 可定制。不要暴露公网。两个宿主可以共用同版本后台；检测到不同版本后台会提示先退出旧后台再启动，不会静默连接旧版，也不会自动杀进程。更新后从统一入口重新进入以取得新的本机会话。

约 18 秒没有发现兼容插件，会跳转 [GitHub 项目](https://github.com/wangge666666/czmykj-yzzh)。未检测到也可能是后台未启动、旧版本、弹窗或浏览器权限被阻止，不能据此断言没安装；已安装者可先启动插件再点击。发布者需另行上传完整客户 ZIP，GitHub 的 Code → Download ZIP 只是源码，不等于可安装客户包。本版本尚未发布线上入口或 GitHub Release。

## 配置一次，然后回原页面创作

登录后打开右下角“账号与创作设置”，主表单只需填写方舟 API Key。模型 ID 默认沿用项目值，实际开通权限以自己的方舟账号为准，必要时在高级设置调整：

- `ARK_API_KEY`：客户自己的方舟 Key。
- `ARK_MODEL`：客户已开通、支持参考视频与参考图的模型或接入点 ID；不能随意填文本模型，不自动猜测权限。
- `MEDIA_UPLOAD_MODE`：`temporary` 自动临时上传，或 `tos` 使用自己的北京 TOS。留空时完整旧 TOS 配置继续走 TOS，否则默认自动上传；不会失败后偷偷换另一家服务。
- `TOS_ACCESS_KEY` / `TOS_SECRET_KEY`：可选，在“火山素材库连接”填写。火山人物库首次提交/同步需要对应账号权限，API Key 不能代替此认证；是否使用 TOS 与人物库权限是两回事。已审核通过的授权人物 ID 沿用原流程复用。
- `TOS_BUCKET`：只有选择自己的北京 TOS 时才填写，并要求上方 AK/SK 有相应桶权限；不接受任意存储地址。
- `ARK_IMAGE_MODEL` / `ARK_PERFORMANCE_MODEL`：可选，图片及表演分析模型，留空沿用原项目默认值。

自动上传使用第三方 [Litterbox 官方 API](https://litterbox.catbox.moe/tools.php)，申请保存 72 小时。图片/参考视频经上传和读取检查后交给模型或人物审核，普通单段参考图片可直接随 API 请求提交。临时文件持链接可访问，插件不支持提前删除、不保证服务长期可用或审核一定通过；不要上传保密或未获授权的素材。每次上传前明确提示目的地，用户确认后才发送。插件不把模型 Key、AK/SK、账号密码发给素材托管方。

保存只做本地格式检查，不会发起付费“连接测试”。Key 输入留空保留已存值，清除有单独确认按钮。配置按 CZMIYOU 账号隔离，保存/清除绑定会话，账号或配置改变会使未提交的旧批准失效。

上传及费用确认使用独立视图，沿用本机已保存配置，不要求重复填写 Key。同一个请求关闭后不会被状态轮询反复弹出；新的请求仍需分别确认。任务运行时修改配置会被拒绝，原配置保留。

临时托管连接不保存服务返回的 Cookie，上传后的读取检查继续使用无 Cookie 连接；显式账号、模型密钥和 Cookie 仍由网络保护拒绝发送。角色缩略图暂时读不到时，卡片提供错误提示和只读重试，不触发素材上传或重新生成。

私有文件位于设置页显示的 `config_path`，通常是 `~/.czmiyou-yzzh/credentials/<用户ID>/.env`。也可把包内空白 `.env.example` 复制到该位置后由客户自行填写：只接受模板中的变量名和单行值，双引号使用 JSON 字符串格式；不执行 shell、不展开变量，也不自动读取系统或其他项目中的 Key。不要把真实配置放进插件包、Git、聊天或截图。

.env 是本地明文配置。程序限制文件权限并避免在正常工具、界面和日志中回显密钥，但无法阻止拥有本机文件权限的人或 Agent 读取。插件不携带平台 Key、数据库密码、登录签名密钥；本地授权控制也不是不可破解的 DRM。

## 人工确认与恢复

- Agent 用 plan 准备素材快照及参数，model 传空字符串即可使用用户设置。计划不上传素材。
- 在工作台检查具体视频/图片、提示词、模型、时长、清晰度、比例、上传目的地和费用承担方后批准。当前没有可靠总价估算，费用以客户自己的供应商账单为准；授权时间卡不等于已批准消费。
- 自动上传先检查返回地址确实可读取原文件，失败则停止本步，不继续提交模型；这不等于供应商侧已接收。选择自有 TOS 时，辅助工具文件位于 `yzzh-plugin/`，链接有效期 24 小时，对象需自行设置生命周期；插件不改桶策略。
- 账号、Key、素材或参数变化后重新计划与批准；Agent 不能代点击批准，不能绕过运行时直接发起生成。
- `submit_uncertain` 表示供应商可能已受理，禁止自动重发。没有任务 ID 时，到供应商控制台核对并联系支持；有 ID 只查询原任务。`download_pending` 只恢复下载，绝不重复生成。
- 时间卡过期或暂时无法验权时不创建新受限任务；已受理任务仍可由原账号取回，已有文件可预览、导出。退出或重启后需原账号重新登录；当前 Key 必须仍能访问原供应商任务。
- 原 0.1.0 中央预览任务保留，但不能变成 BYOK 任务继续提交；若确有历史中央任务需用原版本网关恢复。

自动打码须人工确认是否漏脸；单目深度不是精确 3D 重建。运行时发现缺模型会明确拒绝处理并引导补装，不在处理过程中下载模型。参考视频预检沿用原项目契约；模型是否开通、素材审核与实际兼容性仍需使用客户账号单独验证。

原页面任务位于本地 original/<用户ID>/runs，原仓库历史 runs 不自动并入任何客户账号，不删除历史数据。原流程 TOS 对象前缀沿用 seedance-inputs；清理调用也需要逐次确认，拒绝后对象可能保留，请自行配置生命周期。上文 yzzh-plugin/ 与 24 小时链接只适用于单段辅助工具。

原 UI 仍保留能力入口。基础人脸和深度模型在完整安装时下载；OCR、Demucs、人声分离及其他大型模型不属于基础安装，需另行说明下载内容并取得用户授权后安装扩展和权重。音频子进程禁止联网下载，未配置扩展时明确失败。自动上传只启用上述明确告知的素材托管方，不启用公网隧道或浏览器代操作通道。人物库远端缩略图的兼容性也需真实账号验收。

人物库缩略图通过按账号绑定的本地图片代理读取，不向浏览器或 MCP 返回签名 URL。按用户范围，本版不提供真人活体 H5 或真人授权流程；相关会话请求在本地拒绝，不产生云端请求。虚拟素材仍遵循供应商审核，不伪造审核通过状态。

## 验收边界

本地配置/接口模拟/合成视频、实际供应商生成、真实 CZMIYOU 时间卡、宿主发现和用户视频验收是不同层级。开发仓库的 `docs/plugin-work/czmiyou-yzzh` 分别记录证据。旧中央代收费网关未打入新客户包，不能拿旧测试结果证明新链路已经商用就绪。
