# 米哟无限复刻 · 0.5.0 平台模式开发预览

普通用户安装插件、登录米哟账号后，在原工作台完成创作。衣装智换、虚拟人物复刻重绘、写实虚拟人像复刻重绘三个项目共用平台视频、图片、表演分析、人物库和素材服务，保留各自的分镜、人物绑定和成片步骤。

默认新启动的后台使用 `platform` 模式。方舟 API Key、人物库 AK/SK 和存储配置由管理员保存在服务器；客户端只取得服务状态、模型名称和账户公开信息，不下载共享密钥。产品归属为 `miyo_fashion` / 产品 4，平台操作按米哟账户权限、管理员配置的通道和中央计费规则执行，时间卡资格不等于已批准消费。

这是客户端与平台接口接入的开发预览。**服务器发布、真实账号登录和权限、素材审核、生成结果与中央账单仍需分别验收**；本地测试通过、文件同步或页面显示“已就绪”不能证明这些环节已完成。只更新客户端 ZIP 也不会自动部署服务器或统一登录入口。

## 安装与登录

使用构建后的完整 ZIP，不要直接安装源码骨架。需要 Python 3.10+（推荐 3.12）；首装联网下载依赖和基础本地模型，安装在解压目录，不修改全局 Python。没有 Demucs、PyTorch 或 CUDA 的强制依赖。

完整安装默认包含下面两项基础模型。`setup.py --dry-run` 展示下载内容、来源与保存位置；用户同意插件安装，即包含已告知的这两项基础依赖，已有授权不重复征求确认。权重合计约 50 MB，另需依赖和临时下载空间。

| 基础模型 | 用途 | 下载来源与大小 |
| --- | --- | --- |
| OpenCV YuNet 2023mar | 本地人脸检测和打码 | [OpenCV 模型仓库](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)，约 230 KB |
| Depth Anything V2 Small FP16 ONNX | 本地深度参考 | `onnx-community` 转换版，优先 [ModelScope 镜像](https://modelscope.cn/models/onnx-community/depth-anything-v2-small)，备用 [Hugging Face](https://huggingface.co/onnx-community/depth-anything-v2-small)；49,642,442 字节，约 49.6 MB |

1. 解压到固定位置，先运行 `python3 scripts/validate_release.py`，再运行 `python3 scripts/setup.py --dry-run` 查看安装影响。文件哈希校验不等于发布者数字签名。
2. 用户确认安装后运行 `python3 scripts/setup.py`，安装依赖及上述模型；已有安装授权时直接继续。Windows 使用可用的 Python 命令。`--models` 保留旧命令兼容；只有用户明确选择不安装基础模型时才使用 `--skip-models`，并说明对应打码、深度功能不可用。已有安装缺模型时，先运行 `python3 scripts/setup.py --models-only --dry-run`，再用 `python3 scripts/setup.py --models-only` 补齐；用户要求修复基础模型即涵盖已说明的补装。
3. 运行 `python3 scripts/host_config.py` 输出不含 Key 的绝对路径 MCP 配置，在宿主 MCP 配置入口添加，不覆盖其他 MCP 配置。默认账号接口已内置：`https://mch39t7vkw.coze.site/api/auth/login`。仅管理员变更账号中心时指定 `--login-url`，不能填写不可信地址。
4. Codex 原生插件入口为 `.codex-plugin/plugin.json`；WorkBuddy 提供 `.workbuddy-plugin/plugin.json` 和手动 MCP 配置。宿主版本和 Windows/POSIX 启动命令分别核验；手动添加 MCP 后还需通过宿主技能导入入口导入 `skills/yzzh`。安装元数据有效不代表宿主已发现插件。
5. 网页自动唤醒需要注册本机启动器：先运行 `python3 scripts/register_launcher.py --dry-run`，取得用户对注册的明确同意后再运行 `python3 scripts/register_launcher.py`。macOS 使用当前用户 Applications 下的专用启动器，Windows 只注册当前用户 URL 协议。只启动固定安装目录内的后台，不执行链接参数，不修改其他宿主配置。已有同名启动器不会自动覆盖，更新需明确授权；安装目录不能随意移动。Linux 可先让 Agent 打开插件。
6. 让 Agent“打开米哟无限复刻项目中心”。未登录时进入原来的 CZMIYOU 统一登录页，登录后在“我的应用”点击“米哟无限复刻”。密码只在统一登录页面填写，不交给 Agent；本地页面不要求重复填密码。产品 4 时间卡资格由账号系统验证，员工也不豁免。

统一登录令牌通过限定来源的一次性浏览器交接传入本地后台，再向账号中心验证，只保存在内存，不进入启动协议、GitHub 链接或插件包。退出或重启后从统一入口重新进入。

本地后台默认 `127.0.0.1:7871`，数据目录默认 `~/.czmiyou-yzzh`，可用 `YZZH_DATA_DIR` 定制。统一网页只检测 7871；开发自定义 `YZZH_PORT` 不在自动发现范围内。不要暴露公网。两个宿主可以共用同版本后台；不静默连接不兼容版本，不自动杀进程。已有同版本 BYOK 后台不会因安装或 MCP 连接而自动切成平台模式，应先检查 `health.mode` 并保留运行现场。

约 18 秒未发现兼容插件时，统一入口会前往 [GitHub 项目](https://github.com/wangge666666/czmykj-yzzh)。检测失败也可能是后台未启动、旧版本或浏览器权限问题，不等于确定没安装。发布者须另行上传完整客户 ZIP；Code → Download ZIP 是源码，不等于客户安装包。入口与 Release 的实际发布状态需独立核实。

## 平台服务状态与三个项目

登录后，页面顶部直接显示账号、到期时间、余额、五项平台能力和本地基础自检状态。点击“账号与服务详情”可查看详细检查或退出账号，不显示用户 Key 表单。只有平台报告就绪且所需能力齐全时才显示“平台服务已就绪”；缺少服务时在顶部显示待配置及管理员提示，不让用户反复填写密钥。

三个项目分别位于 `/projects/wardrobe`、`/projects/long-video`、`/projects/real-long-video`。素材经用户确认后上传到米哟平台，再用于当前创作；视频、图片、分析和人物资产操作走服务器接口。服务器负责供应商认证、权限、通道选择和计费，平台失败后不会偷偷改用客户旧 Key、第三方临时托管或其他通道。

管理员需单独部署平台服务，并核实产品 4 权限、通道、模型、人物库、存储及记账配置。客户端支持的接口为 `/api/yzzh/capabilities`、`/api/yzzh/operations` 和 `/api/yzzh/media`；平台入口由管理员配置。状态接口只返回公开能力，供应商密钥不得通过该接口下发。此说明不代替云端部署和真实业务验收。

“本地基础自检”会检查两项模型的完整性、加载推理和视频工具。模型保存在固定运行安装目录 `runtime/models`，不在 Codex 插件缓存重复下载。`health.local_dependencies` 只表示依赖可找到；只有实际模型加载及合成帧推理通过，才能报告本地打码、深度功能就绪。验证不上传客户素材、不调用付费生成；模型变化后重新检查，不在创作途中隐式下载。

本地深度参考和平台生成白模视频是不同步骤，后者可能产生平台费用。OCR、人声分离、Demucs 和其他大型模型不属于基础安装，须说明下载内容并取得授权后安装；音频子进程不能自行联网下载权重。自动打码仍需人工检查漏脸，单目深度不等于精确 3D 重建。

三个项目的白模统一生成穿宽松不透明白色长袖长裤工作服、手套与平底鞋的非写实动画人偶，保留原动作、口型与运镜；最终成片替换占位服装。基础提示、表演补充、质量纠偏和页面说明采用同一要求。供应商拒绝输出不代表已查明具体触发原因；模板修改不保证通过审核，不自动重发被拒绝的任务。

## 请求确认、人物审核与恢复

平台三个项目按本次点击的步骤确认一次：面板提前展示本步骤包含的素材上传、模型调用、用途和费用。用户确认后，范围内的上传、分析或生成连续执行，不按每份素材重复询问；取消会停止本步骤的后续请求。批准只绑定本次操作、账号、会话、配置和选定输入，不跨新步骤或新点击复用；每个请求仍冻结参数、核对素材并保留独立发送记录。旧版页面的单次上传确认不会扩大为整个步骤批准。Agent 没有批准工具，也不能通过浏览器或 HTTP 代点批准。

同一步骤确认后不会因状态轮询或后续素材上传反复弹出，新点击的步骤重新确认。正常发送中不误报为结果不明；平台查询暂未找到回执时保留记录，不重新上传或生成。确认任务不需要填写或保存 Key。平台余额无法读取时显示未知，不当作零余额；金额和最终费用以平台账单为准，不编造总价估算。

本版只提供 AIGC 虚拟人物流程，写实虚拟人像也不等于真人活体认证。首次提交虚拟人物素材时，用户须明确勾选“我确认拥有该虚拟人物素材及本次用途的使用权，并同意提交平台审核”；每次新的入库步骤对本次所选素材重新确认，不预勾选、不代替用户声明。审核状态由平台返回，Active 后复用人物 ID，不伪造通过状态、不为已有 ID 重复上传。缩略图失败先只读重试，不能用重新上传或生成代替预览修复。

结果不明的请求保留网络记录，阻止继续创建云端修改。通过“查询原请求”只读取原请求状态，不重新发送生成请求；只有匹配原请求的明确回执才更新本地状态。没有明确受理或完成证据时，由管理员核对原请求及中央账单；有任务 ID 时仅查询原任务，`download_pending` 只恢复下载。不得删除记录、切换账号或更换通道来规避不确定状态。

平台原页面数据按账号保存在 `original/<用户ID>/platform`；BYOK 原数据保留在 `original/<用户ID>`。浏览器草稿也按账号和模式隔离，平台不自动恢复旧 BYOK 草稿。原仓库历史 `runs` 不自动归入客户账号，不删除旧素材、任务或未决记录。时间卡过期时不创建新的受限任务；既有任务恢复仍需原账号及原平台记录，具体权限由服务端核实。

## MCP 使用与历史 BYOK 兼容

先用 `health` 核对连接、版本、登录和实际运行模式，再查询已有任务，避免重复处理。默认 `open_workbench` 打开原项目首页。`original_analyze` 可在虚拟或写实虚拟人像项目创建本地拆镜任务；用 `original_status` 查询原流程 job ID，再回原页面继续。其余原工作流由用户在页面执行，不声称所有按钮都有 MCP 工具。

`import_video`、`process`、`status`、`list_projects`、`export` 保留本地辅助用途。单段辅助任务和原页面任务是不同的 ID。平台模式禁止旧单段 `plan`、`submit`、`poll` 云端入口并提示使用三个项目工作流，不暗中调用旧 BYOK 供应商。

`byok` 仅用于用户明确选择的历史兼容：运营者在确认没有运行中或结果不明任务、保留记录并安全退出旧后台后，可使用固定安装环境启动 `python -m yzzh_local.app --mode byok`。不能把模式切换作为安装、连接失败或恢复失败的隐含步骤；MCP 检测到同版本后台时保持原模式，不自动重启或切换。

在显式 BYOK 模式下，用户自己的供应商账户承担生成费用，不使用新平台中央计费。用户在本地设置表单填写 `ARK_API_KEY`；可配置 `ARK_MODEL`、`ARK_IMAGE_MODEL`、`ARK_PERFORMANCE_MODEL`。`MEDIA_UPLOAD_MODE=temporary` 使用旧第三方 [Litterbox API](https://litterbox.catbox.moe/tools.php)，申请保存 72 小时，持链接可访问且不能提前删除；`tos` 使用用户自己的北京 TOS。旧完整 TOS 配置可沿用，不在失败后自动换托管方。人物库需要有权限的 `TOS_ACCESS_KEY` / `TOS_SECRET_KEY`，自有存储还需要 `TOS_BUCKET`。Key、AK/SK 和密码不发给临时托管方，Cookie 与凭据隔离不能关闭。

BYOK 配置按账号保存在设置页显示的 `config_path`，通常是 `~/.czmiyou-yzzh/credentials/<用户ID>/.env`，属于本地明文文件。只读公开标志即可排障，不读取真实凭据、不放入聊天、Git、日志或插件包。保存只做本地格式检查，不是付费连接测试；留空保留已存 Key，清除有独立确认。已保存 Key 自动复用，任务运行时拒绝改配置并保留原值。旧辅助计划的预览和批准页为 `open_workbench(view="agent")`，该流程不适用于平台模式。

旧 BYOK 任务仍属于原供应商账号和通道，不迁移到平台重新提交；旧中央预览任务也不能冒充 BYOK 或新平台任务恢复。已有 TOS 对象生命周期由原用户配置，清理云端对象仍须明确确认；插件不靠删数据消除异常。

## 更新与验收

开发修改遵守仓库 `AGENTS.md`：每个明确步骤验证后单独 Git 提交，并同步源码、完整插件包、固定运行目录和注册缓存，备份被替换文件并更新校验清单；不把服务器凭据打包。当前进程是否加载更新、服务器是否部署、真实工作流是否通过需分别记录。有运行中或结果不明的任务时，不强杀后台、不清记录、不重复生成来应用更新。

本地合成测试、插件发现、模型推理、真实登录和授权、平台素材与生成、中央账单及用户视频验收是不同证据。证据记录在开发仓库 `docs/plugin-work/czmiyou-yzzh`；没有实际验证的环节保留待验收状态，不能用历史 BYOK 或旧中央预览测试代替新平台验收。

## 已有公司角色库

登录后，三个项目读取画布和创作中心当前通道的公司角色库，并显示本账号在插件中新建的角色。已有角色直接复用原 Asset ID；无需重新填写 AK/SK、迁移旧缓存或重复上传。公司共享角色可选择使用，管理操作仍在画布/创作中心完成。

平台需部署支持 `canvas-shared-v1` 的创作中心版本。旧服务会明确提示管理员更新；读取失败保留错误和当前通道的缓存，不能报告为正常空库。角色库超过 100 个记录会继续分页；切换账号或通道不沿用其他范围缓存。刷新只读取角色与预览，不创建生成任务。

安装脚本最后自动核对运行文件校验值、Codex/WorkBuddy 插件清单、三个项目页面、基础模型推理和 FFmpeg，并写入 `installation-check.json`。任一项失败都不能报告完整安装成功。既有安装可运行 `python3 scripts/setup.py --check-only`，只做离线检查并更新报告，不安装、不下载、不读取客户素材。

交付给用户前，安装端还需通过插件 `health` 和工作台确认实际平台模式、登录以及角色库读取。离线检查完成不等于线上服务已经部署或真实生成已经通过。服务未就绪时由管理员处理，不要求终端用户重填供应商凭据。

### 分析异常在工作台内继续

虚拟人物和写实虚拟人像项目都保留逐镜台词、表演和打码结果。跨镜人物对应的回复格式错误或漏掉人物时，工作台显示“人物对应待核对”；点击即可进入逐镜人物列表。核对只使用本地结果，不再次上传、调用分析或收费；未知人物必须明确选择，生成前仍需确认人物与场景。网络中断或原请求结果不明继续保留回执并查询原请求，不自动重发。
