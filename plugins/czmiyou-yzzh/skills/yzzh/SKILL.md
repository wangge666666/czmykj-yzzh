# 衣装智换

通过 `czmiyou-yzzh` MCP 操作用户选择的视频。CZMIYOU 产品 4 时间卡控制使用资格；本地程序使用客户自己的方舟 Key，素材默认自动上传，TOS 为可选高级设置，不扣中央余额。Agent 不绕过运行时直接调用付费接口。

- 先 health / list_projects，已有项目先 status，避免重复导入和生成。缺少连接时读取插件根 README，不要猜端口或伪造成功。
- 用 open_workbench 打开工作台：未登录时进入原来的 CZMIYOU 统一登录页面，登录后点击「我的应用 → 米哟衣装智换」进入本地原界面。不要使用本地旧密码表单作为正常入口。密码只能由用户在统一登录页面填写，API Key 由用户在本地设置表单填写；不能索取到聊天、放入 MCP 参数或读取连接文件/.env 中的凭据。先完成登录和本地模型设置，再创建受限任务；MCP 没有登录、写密钥或批准工具。
- 默认主入口是原项目首页和原有流程，不把单段辅助页面当作替代界面。original_analyze 接受用户明确选择的本地视频，project 选 virtual 或 real；original_status 用原版 12 位 job_id 查询。原页面能继续使用该拆镜任务。其他原流程由用户在原页面执行，不伪造尚不存在的 MCP 操作。
- 原流程外发会在右下角面板等待用户逐次批准。没有批准工具；不得自动点击同意。显示 uncertain/sending 未确认时停止新云端操作并核对供应商，不能删除本地网络记录来解锁。
- 已保存的 Key 自动复用；上传/费用确认使用独立视图，不让用户为确认任务重复填写或保存配置。同一请求关闭后不因轮询再次弹出，新请求仍分别确认。用户反馈“又要填 Key”时先查公开配置标志和待确认请求，不索取密钥；任务运行时的配置保存 409 不代表旧 Key 丢失。
- plan/submit 单段辅助工具的审批页面用 open_workbench(view="agent") 打开；默认不传 view 打开原项目首页。
- import_video 只导入用户明确指定的本地文件；process 可 split、mosaic、depth。超过 14.5 秒的参考先分镜。完整安装已包含基础人脸和深度模型；运行中缺模型时明确报告缺失并引导补装，不在媒体处理过程中下载。用户要求补齐或修复时，按下方安装流程处理。异步任务用 status 读取实际结果。
- 原始视频、人脸打码、深度参考用途不同。让用户检查打码是否覆盖所有人脸及参考视频是否合适，不把“处理完成”当作隐私已验收。
- 首版生成闭环是单段参考重绘：plan 使用选中的视频产物和 1—3 张用户参考图、明确的提示词/时长/比例/分辨率；model 传空字符串使用用户设置的已开通模型，不猜测其权限或兼容性。不要用供应商 URL 代替本地素材。
- plan 在本地准备素材快照和方案，不上传媒体、不请求中央价格。打开工作台让用户检查精确视频/图片、用途、实际上传目的地与方舟、费用承担方。自动上传使用第三方 Litterbox，持链接可访问，申请保存 72 小时且插件不能提前删除；保密或未授权素材不应上传。当前不提供可靠总价估算，账单以用户供应商为准。未经用户检查并批准，不调用 submit；不得通过脚本、浏览器自动化或 HTTP 代替用户点击批准。
- submit 会上传并产生费用。账号、Key、模型、上传方式、素材或参数改变后必须重新规划和确认；本地运行时已拒绝过期批准，不绕过门禁。默认无需 TOS；已有完整 TOS 配置继续沿用，切换必须由用户在设置页完成，不暗中回退、启用公网隧道或改用其他托管方。
- 主设置只要求方舟 API Key；新增或同步人物库仍需客户在折叠的“火山素材库连接”中填写有权限的 AK/SK，这不是存储桶要求。审核通过的授权人物 asset ID 沿用原链路复用，不为已有 ID 重复上传。本版只提供 AIGC 虚拟人像审核流程，不展示真人授权入口、不要求真人认证；仍需正常素材审核，不伪造 Active 状态。
- submit_uncertain 表示可能已受理，只尝试查询已有任务；缺少任务 ID 时提示到供应商控制台核对，停止自动恢复，不自动重新创建 plan 或提交。download_pending 只恢复下载，不再生成。旧中央预览任务不能冒充 BYOK 任务，保留旧数据并报告需原网关恢复。
- 时间卡到期或授权服务不可达时，不创建新受限任务；已提交任务仍可查询取回。退出后需原账号重新登录才能恢复；更换 Key 可能无法访问原供应商账号任务，应提示用户在设置页处理，不能索取 Key。
- 成功后通过工作台预览下载结果，用 export 复制到用户指定的新文件。报告实体路径及是否解码/人工检查，不把云状态代替视频验收。
- 原网页和业务代码已接入账号隔离层，但人物资产库、表演分析、白模和完整生成尚待真实供应商验收。OCR、人声分离和其他大型模型是另装扩展，不属于基础安装；需说明内容并另行取得用户授权。已有单段工具的预览/批准仍在 /agent-workbench，不与原工作流 ID 混用。

安装时读取插件根 README，先 validate_release.py 和 setup.py --dry-run，向用户说明安装目录、依赖及基础模型下载内容：OpenCV YuNet 2023mar 人脸模型约 230 KB，Depth Anything V2 Small FP16 ONNX（onnx-community 转换版）约 49.6 MB，来源与位置以安装预览为准。默认 setup.py 在解压目录安装依赖及这两项基础模型；用户同意插件安装即涵盖已说明的基础依赖，已有安装授权就继续执行，不再要求额外确认模型下载。--models 保留兼容；仅用户明确选择跳过基础模型时使用 --skip-models，并说明缺失模型对应的打码、深度功能不可用。已安装插件缺基础模型时，用 setup.py --models-only --dry-run 展示补装内容，再运行 setup.py --models-only；用户要求补齐或修复基础模型时直接完成已说明的补装。

模型只放在固定运行安装目录的 runtime/models，不需要在 Codex 插件缓存重复下载。health 的 local_dependencies 只证明 Python 依赖可找到，不证明模型权重已齐；必须通过安装脚本的实际模型加载和本地合成帧推理验证后，才能报告打码、深度功能就绪。验证不使用客户素材、不上传媒体、不调用付费生成；不能仅凭依赖安装成功或文件存在就宣称基础安装完成。

安装及配置验收时，检查工作台「账号与创作设置 → 本地基础自检」：两项模型须通过完整性及实际推理检查，视频工具须能执行；缺失或损坏按安装流程补齐，不能让用户到处理素材时才发现。只读自检、API Key 本地保存和实际供应商生成是不同证据，不能把前两项报告为付费链路已通过。缩略图失败用卡片的只读重试或刷新角色库，保留用户当前素材与任务；不要因预览失败重新上传、生成或清空配置。临时托管 Cookie 与模型凭据应隔离，不能为消除报错而关闭凭据拦截。

网页自动唤醒还需 register_launcher.py：先 --dry-run，并取得用户对本机 URL 启动器注册的明确同意，不能作为隐含安装步骤；不会覆盖已有处理程序。线上入口固定检测 7871，不改默认端口；检测失败解释为未检测到而不是确定未安装。无需独立视频中转后台；不要部署服务、修改全局宿主或更换用户配置作为隐含步骤。统一登录系统也须发布配套改动，源码包不等于可安装客户 ZIP。

这是待真实登录、时间卡、供应商生成和双宿主验收的技术预览；配置成功、模拟测试通过或安装包存在都不表示客户正式可用。
