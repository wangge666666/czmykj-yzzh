# 米哟无限复刻

通过 `czmiyou-yzzh` MCP 和原工作台处理用户选择的视频。普通用户安装后登录米哟账号，三个项目共用平台视频、图片、分析、人物库和素材服务。供应商 Key、人物库 AK/SK 和存储配置由管理员留在服务器；客户端不取得共享密钥，平台按产品 4 / `miyo_fashion` 权限、通道和中央计费执行。

## 开始与模式检查

- 先 `health` 核对连接、版本、登录和实际 `mode`，再 `list_projects`；已有辅助任务先 `status`，原页面任务用 `original_status`，避免重复导入和生成。缺连接时读插件根 README，不猜端口、不伪造成功。
- 新后台默认 `platform`。已运行的同版本 `byok` 后台不会因 MCP 连接自动改模式；先报告实际模式和任务状态，不自动重启、迁移或改用旧 Key。有运行中或结果不明任务时保留现场。
- `open_workbench` 和统一登录交接均默认打开三个项目的选择首页 `/`。未登录时进入原 CZMIYOU 统一登录页面，用户登录后点击“我的应用 → 米哟无限复刻”；不用旧本地密码表单。密码只由用户在统一登录页填写，不索取到聊天、不读取连接文件或 `.env` 内的凭据。MCP 没有登录、写密钥或批准工具。
- 三个项目一起维护：`/projects/wardrobe`、`/projects/long-video`、`/projects/real-long-video`。保留各自分镜、人物绑定和成片策略，不把旧单段辅助工具当成替代工作台。
- 平台模式顶部直接显示账号、到期时间、余额、平台能力和本地基础自检状态，详细检查与退出账号在“账号与服务详情”中，不要求 Key。若待配置，查看顶部公开失败信息并定位管理员平台部署、权限或能力配置；不让用户重填供应商凭据，不回退 BYOK。只读状态为就绪不等于真实生成或账单验收通过。

## 本地准备与平台创作

- `original_analyze` 只接受用户明确选择的本地视频，`project` 选 `virtual` 或 `real`；用 `original_status` 查询原版 12 位 job ID，再回原页面继续。其他原工作流由用户在页面执行，不伪造不存在的 MCP 操作。
- `import_video` 只导入指定本地文件，`process` 可做 `split`、`mosaic`、`depth`，异步结果用 `status` 查询。本地辅助参考超过 14.5 秒先分镜；原页面遵循各自预检规则。完整安装包含基础人脸、深度模型，缺失时补装，不在处理用户素材时偷偷下载。
- 本地深度参考与平台生成白模视频用途及费用不同。打码完成仍须人工检查是否漏脸；单目深度不等于精确 3D。不能拿本地处理成功证明平台白模或最终视频已生成。
- 平台三个项目以用户本次点击的步骤为确认范围。面板一次展示本步骤的素材上传、模型调用、用途与平台费用，用户确认后同一步骤的请求连续执行，不按每份素材重复弹窗。范围绑定本次操作、账号、会话、配置及所选输入；每个请求仍校验冻结正文并保留独立发送记录。旧页面只批准单次上传时不得扩展到整个步骤。Agent 不代点击同意、不通过脚本或 HTTP 绕过批准。
- 确认任务不需要填写或保存 Key。同一步骤确认后不因轮询或后续素材请求重复弹出；正常发送中显示为运行进度，不当作结果不明。新点击的步骤须重新确认，取消会停止本步骤后续发送，结果不明仍暂停新请求。用户说“又要填 Key”时，先检查公开模式、配置标志与待确认请求，不索取密钥。
- 平台费用由米哟账户按管理员配置的通道和价格计费，不编造总价；无法获取余额时保留未知状态。时间卡资格不等于已批准消费。账号、模式、素材或参数改变后，旧批准不得沿用。
- 只提供 AIGC 虚拟人物流程，包括写实虚拟人像；不要求真人活体认证，不提供绕过审核的方法。每次新的虚拟人物入库步骤必须由用户明确勾选本次所选素材的使用权与审核同意，不预勾选、不代做声明。Active 后复用人物 ID，不能伪造审核通过或为已有 ID 重复上传。
- 角色缩略图读取失败先用只读重试，保留当前素材与任务；不因预览失败重传、重生成或清配置。平台模式不能退回第三方临时托管、客户旧 Key 或公网隧道。

## 结果不明与历史任务

- 白模三个项目统一使用穿完整白色长袖长裤工作服、手套与平底鞋的非写实动画人偶；保留动作与口型，最终成片替换占位服装。输出审核拒绝不能仅凭提示文案断定具体原因；调整基础、表演与纠偏提示时保持穿着要求一致，不自动重发、不宣称已经通过真实审核。

- 台词与表演已完成、跨镜人物对应返回格式错误或缺少槽位时，两个人物项目在工作台显示“人物对应待核对”。点击“核对人物对应”直接进入逐镜列表，只修改本地人物映射；不重填 Key、不重复上传或付费分析。已收到的跨镜回复保存在原任务目录，重复操作优先复用。旧任务的明确格式失败可由状态查询恢复；未知回执不能冒充格式错误，也不能自动重发。

- `sending` / `uncertain` 表示请求可能已受理，停止新的云端修改并保留记录。可通过“查询原请求”只读核对原请求，不重发；只有匹配原请求的明确回执才更新本地状态。有任务 ID 时只查询原任务，无明确结果时请管理员核对原请求及中央账单。`download_pending` 只恢复下载。
- 平台任务目录和浏览器草稿按账号、模式隔离，不自动恢复旧 BYOK 草稿。旧供应商任务不能切平台重新提交，原仓库历史 runs 不自动归入客户账号；不删除素材、任务、账单或未决网络记录来消除异常。
- 资格过期不创建新受限任务；原账号可按服务端权限查询既有任务，重启或退出后重新从统一入口登录。恢复仍属于原账号和原通道，不以切账号或换通道代替恢复。
- 输出通过原工作台预览和下载，辅助产物可用 `export` 复制到用户指定的新文件。报告实际路径、是否解码及是否人工检查，不把云状态当作视频验收。
- 平台模式下旧单段 `plan`、`submit`、`poll` 被拒绝，应回到三个项目工作流；本地 `import_video`、`process`、`status`、`list_projects`、`export` 仍可使用，不混淆两套任务 ID。

## 仅显式选择的 BYOK 兼容

用户明确需要恢复历史 BYOK 时才使用此模式。先检查运行任务和未决记录，保留数据并安排安全退出；运营者可用固定安装环境的 `python -m yzzh_local.app --mode byok` 显式启动。不能把切模式、停进程或迁移数据作为安装和排障的隐含动作。

BYOK 使用客户自己的供应商账户付费，不走新平台中央计费。用户只在本地表单填写方舟 Key、可选模型和有权限的人物库 AK/SK，不交给 Agent。旧完整 TOS 配置可以沿用；默认旧临时上传使用 Litterbox，申请保存 72 小时、持链接可访问且不能提前删除。每次外发仍说明目的地并等待用户确认，不自动换托管方，不关闭 Cookie 与凭据隔离。

BYOK 已存 Key 自动复用，空输入保留原值，清除独立确认；任务运行时配置保存 409 不代表旧 Key 丢失。查看公开标志即可，不读取真实配置。旧单段 `plan` 本地准备选中的视频和 1—3 张参考图、提示词及参数，`model` 可传空使用已存设置；`open_workbench(view="agent")` 仅用于此辅助流程的预览与批准。用户批准后才可 `submit`，`poll` 只查询原任务；结果不明不重发。旧中央预览任务也不能冒充 BYOK 或新平台任务。

## 安装、基础自检与更新

先读取插件根 README。运行 `python3 scripts/validate_release.py` 和 `python3 scripts/setup.py --dry-run`，说明固定安装目录、依赖及模型下载内容：OpenCV YuNet 2023mar 约 230 KB，Depth Anything V2 Small FP16 ONNX（onnx-community 转换版）约 49.6 MB，来源与位置以预览为准。

`python3 scripts/setup.py` 默认安装依赖及两项基础模型，用户同意安装已涵盖告知的基础依赖，已有授权直接继续，不重复要求模型许可。`--models` 保留兼容；只有明确选择跳过时用 `--skip-models` 并说明缺失功能。补装先 `python3 scripts/setup.py --models-only --dry-run`，再 `python3 scripts/setup.py --models-only`；用户要求修复即涵盖已说明的补装。

模型只在固定运行安装目录 `runtime/models` 保存，不在插件缓存重复下载。`health.local_dependencies` 只说明依赖可找到；“本地基础自检”须通过文件完整性、实际模型加载、合成帧推理和视频工具检查。验证只用本地合成内容，不上传、不付费；不能只凭文件存在报告完整安装。OCR、Demucs、人声分离及其他大模型是另装扩展，须说明内容并取得授权，音频子进程不得自行联网下载。

网页自动唤醒另需 `register_launcher.py --dry-run`，取得本机 URL 启动器注册的明确授权后才执行注册，不作为隐含安装步骤，不覆盖已有处理程序。线上入口固定检测 7871；失败解释为“未检测到”，不确定说没安装。不要隐含修改全局宿主配置、部署服务器或更换用户设置。源代码 ZIP 不等于客户安装包；统一登录入口与平台服务也需单独发布。

开发改动遵守仓库 `AGENTS.md`：每个明确步骤验证后单独 Git 提交，并备份、同步源码、完整插件包、固定运行目录和注册缓存，更新构建与校验清单。分别记录文件同步、当前进程加载、服务器部署和真实验收；有运行中或不明任务时不强停、不清记录、不重复生成来加载更新。同步涉及的 Skill、脚本及说明，服务器凭据不进入客户端包。

当前是平台接入开发预览。模型自检、合成测试、宿主发现、真实登录与时间卡、平台素材/审核/生成、中央账单和用户视频验收分别核实；未验收环节明确保留，不用旧 BYOK 或中央预览结果代替。

## 角色库验收

三个项目共用画布当前通道的公司角色库及本账号插件角色。检查共享角色是否能读取、预览和选择，并检查共享素材无删除入口、无上传目标；服务端生成前还会核对实时审核与通道。不把历史 BYOK 的分组数当作平台真实角色数，不复制缓存或重新上传修复列表。发现 `canvas-shared-v1` 缺失时，提示管理员部署创作中心共享角色更新，不要求用户重填 Key。错误信息与缓存提示必须保留，分页不能只读前 100 条。

虚拟人物项目也提供已有角色下拉选择，按人物槽位绑定原 Asset ID，不要求用户抄写 ID；刷新列表保留已选角色和本地文件。角色未在本次列表中确认时显示“待核验”，不得自动换成其他角色。

完整安装以 setup 最终离线验收通过为准：校验运行文件、Codex/WorkBuddy 包、三项目页面、基础模型合成推理和 FFmpeg。只下载文件或安装依赖不算完成；失败保留诊断并补齐，不让用户进入创作后才发现。更新或排障可执行 `python3 scripts/setup.py --check-only`，不安装或下载，结果写入 `installation-check.json`。随后 `health` 核对当前进程模式，登录后只读检查角色库，明确区分宿主文件、宿主已发现、实际进程和线上部署；不得以离线报告冒充真实付费验收。

## 2026-09-15 功能同步

工作台已包含动作迁移、动态人物/物品/背景替换、按秒改写与 1–4 人物绑定。衣装智换的每个人物可选上传服装，未上传沿用该人物形象图；支持预览、更换和删除。衣装智换的模型按当前用户要求去除服装，采用红、白、黄、蓝身份绑定，该规则优先于旧版占位工作服说明。

原片上传打码流程按最多 15 秒分段，短片以黑场补足生成参考时长，输出恢复原时长并合成。白模和替换成片保留原片对白，旧静音结果可免费补音；修复闭嘴画面仍需重新生成并预览。素材库直接引用和按秒改写保留各自时长检查。代码与包内模块已同步；此记录不表示新版功能已通过真实平台生成、计费或其他电脑安装验收。
